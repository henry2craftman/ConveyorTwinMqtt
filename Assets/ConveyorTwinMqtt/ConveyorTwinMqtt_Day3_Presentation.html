DAY 03 / 실습 02

Scene A와 B를 동시에 실행합니다

권장 실행 구성

  1. A를 독립 실행 파일로 빌드하여 실행합니다.
  2. B는 Unity Editor에서 Play합니다.

반드시 확인

  • 서로 다른 PC라면 Broker PC의 주소를 사용합니다.
  • A의 발행 로그와 B의 적용 로그를 함께 확인합니다.

확인 질문 · 완료 기준A에서 Start를 눌렀을 때 B의 감지·모터·계측값이 갱신된다.

강사 노트

한 Editor에서 A를 끄고 B 씬만 여는 구성은 A가 동시에 발행하지 않습니다. 기본 메시지에는 제품 위치·생성 이벤트가 없어 제품 궤적까지 복제되지는 않습니다.

DAY 03 / 실습 03

운전 JSON을 수동으로 발행합니다

{
  "schema": "factory.conveyor.state.v1",
  "source": "mqtt-explorer",
  "quality": "good",
  "connected": true,
  "state": {
    "objectDetected": true,
    "conveyorMotorOn": true
  },
  "measurements": {
    "temperatureC": 41.8,
    "vibrationMmS": 1.2,
    "currentA": 3.1,
    "rpm": 1420
  },
  "status": {"level": "normal"},
  "raw": {"Y20": true, "X0": true}
}

테스트 순서

  1. A 발행을 멈춥니다.
  2. Explorer에서 state 토픽을 선택합니다.
  3. 왼쪽 JSON 전체를 발행합니다.
  4. B의 모터 ON과 RPM 1420을 확인합니다.

확인 질문 · 완료 기준Topic: factory/line1/conveyor/state

강사 노트

현재 Subscriber로 시험할 최소 예제입니다. 운영 규격 검증에서는 lineId·mode·timestamp 등 전체 메시지 필드도 확인합니다.

DAY 03 / 실습 04

정지 JSON은 비트와 수치를 함께 맞춥니다

{
  "connected": true,
  "quality": "good",
  "state": {
    "startButton": false,
    "objectDetected": false,
    "conveyorMotorOn": false
  },
  "measurements": {
    "temperatureC": 28,
    "vibrationMmS": 0.2,
    "currentA": 0.1,
    "rpm": 0
  },
  "status": {"level": "idle"},
  "raw": {"Y20": false, "X0": false}
}

기대 결과

  • 모터 표시 OFF
  • 컨베이어 정지
  • RPM 0
  • 감지 표시 OFF

Rotate Motor Only When Motor On을 켜면 출력 OFF일 때 로터를 회전시키지 않습니다.

확인 질문 · 완료 기준startButton=false만 보내는 것과 모터 출력 OFF를 보내는 것의 차이를 설명한다.

DAY 03 / 개념 02

raw 우선 적용의 범위를 확인합니다

입력설정적용 결과
state.motor=true / raw.Y20=falsePrefer Raw Device Values ON모터 OFF + 불일치 경고
state.motor=true / raw.Y20=falsePrefer Raw Device Values OFFstate 기준 모터 ON
raw.D130=0 / measurements.rpm=1420현재 코드RPM 표시값은 measurements 기준

표의 state.motor는 state.conveyorMotorOn을 줄여 쓴 표현입니다.

확인 질문 · 완료 기준Y20·X0 비트 우선 처리와 D 레지스터 배율 변환을 혼동하지 않는다.

강사 노트

정상 메시지는 두 표현이 일치해야 합니다. 우선순위 옵션은 잘못된 데이터를 올바른 데이터로 만드는 기능이 아닙니다.

DAY 03 / 오류 클리닉

로그로 문제가 생긴 단계를 찾습니다

관찰 결과다음 확인
Subscribed만 표시발행자가 실행 중인지, 토픽이 같은지
Message queued 없음Host·Client ID·토픽·JSON 해석 오류
queued는 있지만 Applied 없음컴포넌트 활성 상태·Update·Console 오류
Applied는 있지만 Text 고정Dashboard·TMP 참조·중복 UI 제어
정지시켰는데 다시 움직임다른 발행자가 값을 덮는지
Y20 OFF인데 RPM만 남음measurements.rpm과 회전 조건

확인 질문 · 완료 기준연결 → 수신 → 적용 → 표시 순서로 증거를 확인한다.

DAY 03 / 장애 실습

마지막 값이 최신 값인지 확인합니다

  1. A에서 정상 메시지를 한 번 이상 발행합니다.
  2. A의 발행을 중지하고 B 화면을 관찰합니다.
  3. Console 수신 횟수와 화면에 남은 값을 비교합니다.
  4. Broker도 중지한 뒤 연결 상태와 수신 상태를 구분합니다.

확인 질문 · 완료 기준질문: 화면에 1,420 RPM이 남아 있다는 사실만으로 현재 운전 중이라고 말할 수 있는가?

강사 노트

현재 최초 수신 대기 경고는 수신 후 stale 감시가 아닙니다. 마지막 수신 시각·시간 초과 표시·재접속 정책은 추가 구현 항목으로 기록합니다.

DAY 03 / 확장 설계 01

부드러운 회전과 정확한 위치는 다릅니다

현재 구현

  • RPM으로 로터를 매 프레임 회전시킵니다.
  • Motor Rotation Scale은 시각화 배율입니다.
  • Y20으로 컨베이어 구동 상태를 맞춥니다.

심화 과제

  • 제품 ID·생성 이벤트·위치·시각을 메시지에 추가합니다.
  • 수신 주기 사이의 위치를 보간합니다.
  • 예측 위치와 실제 수신값의 오차를 보정합니다.

확인 질문 · 완료 기준상태 미러링과 제품 궤적 동기화의 차이를 설명한다.

강사 노트

현재 기본 메시지만으로 동일 제품 위치나 모터의 절대 회전 위상을 보장하지 않습니다. LERP·Dead Reckoning은 위치 메시지 설계 후 확장합니다.

명령과 상태를 별도 경로로 설계합니다

요청을 보냈다는 사실과 설비가 실제로 동작했다는 사실을 구분합니다.

확인 질문 · 완료 기준요청 거부·시간 초과·중복 요청 처리 방법을 팀별로 제안한다.

강사 노트

현재 스크립트의 기본 범위는 상태 발행·구독입니다. 원격 명령·인터록·비상 정지 기능은 추가 설계 과제이며 MQTT 화면 버튼이 실제 비상 정지 회로를 대체하지 않습니다.

DAY 03 / 통합 검증
