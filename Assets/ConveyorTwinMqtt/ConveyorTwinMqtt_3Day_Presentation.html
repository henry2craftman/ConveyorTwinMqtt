PLC 없이 시작하는 산업 디지털 트윈 XR 실습

컨베이어 디지털 트윈: Unity A - MQTT - Unity B

Start 버튼, 물체 낙하, 근접센서, 컨베이어, RPM/온도/진동/전류 대시보드를 통해 PLC의 X/Y 개념과 MQTT 기반 원격 미러링을 3일 동안 완성합니다.

Mock PLC Y20 출력 X0 입력 MQTT Pub/Sub Fault Injection Checkpoint 복구

학습 목표

교육생이 마지막에 할 수 있어야 하는 것

지식 목표

  • PLC의 입력 X, 출력 Y, 워드 데이터 D를 구분한다.
  • Unity 메인 스레드와 MQTT 수신 콜백을 분리해야 하는 이유를 설명한다.
  • Raw 디바이스 값을 의미 기반 JSON으로 바꾸는 이유를 말할 수 있다.
  • 통신 두절, 값 불일치, 이상 수치가 왜 위험한지 이해한다.

실습 목표

  • Scene A에서 Start 버튼으로 물체를 떨어뜨린다.
  • 근접센서 감지로 X0를 만들고, Mock PLC가 Y20을 켜게 한다.
  • Scene A가 MQTT로 상태를 발행한다.
  • Scene B가 MQTT를 구독해 컨베이어와 대시보드를 동기화한다.
강의 중심 질문: 이 신호는 어디서 생겼고, 어떤 이름으로 바뀌며, 최종적으로 무엇을 움직이는가?

스레드 안전

MQTT 콜백에서 Unity 오브젝트를 바로 건드리지 않는다

문제 상황

// 위험한 예
void OnMqttMessageReceived(...)
{
    motorRotor.Rotate(...); // Unity 메인 스레드가 아닐 수 있음
}

네트워크 수신 콜백은 Unity의 Update()와 다른 스레드에서 올 수 있습니다.

우리 코드의 해결

OnMqttMessageReceived()
→ Queue에 메시지 저장

Update()
→ DrainMessages()
→ ApplyMessage()
→ Unity 오브젝트 변경

ConveyorMqttSubscriber는 Queue를 통해 Unity 메인 스레드에서만 화면을 바꿉니다.

자주 나오는 질문

교육생이 헷갈리는 지점 정리

Y20은 출력인데 왜 Motor On인가?

PLC 입장에서는 출력이고, Unity 입장에서는 “컨베이어 모터가 켜지라는 신호를 받았다”는 상태입니다.

Y20 ON  → conveyorMotorOn = true
Y20 OFF → conveyorMotorOn = false

raw.Y20과 state 값이 다르면?

교육용 구독자는 raw 값을 우선 적용하도록 보강했습니다. Console 경고를 보고 메시지 불일치를 찾습니다.

state.conveyorMotorOn = true
raw.Y20 = false
→ raw.Y20 기준으로 정지

Fault Injection

실패를 일부러 만들어 원인을 찾게 한다

1. Unity 메인 스레드 위반

MQTT 수신 콜백 안에서 직접 transform.Rotate()를 호출하게 해 보고, Queue가 필요한 이유를 설명합니다.

2. Broker 중단

Mosquitto를 끄고, 마지막 값만 남는 위험과 stale 상태 표시의 필요성을 토론합니다.

3. Topic 오타

factory/line1/conveyor/state를 일부러 틀리게 보내고 구독 로그와 수신 로그를 비교합니다.

4. 값 불일치

state.conveyorMotorOn과 raw.Y20을 다르게 보내서 어떤 값이 우선되는지 확인합니다.

복구 운영

15분 이상 막히면 복구 패키지로 다음 단계에 태운다

체크포인트

  • Checkpoint 1: Scene A Mock 흐름 완성
  • Checkpoint 2: MQTT Explorer 수동 publish/subscribe 성공
  • Checkpoint 3: Scene A → MQTT → Scene B 동기화 성공

복구 기준

  • Console 첫 오류를 기록한다.
  • Inspector 연결 누락을 확인한다.
  • Topic, Broker IP, Port를 확인한다.
  • 미해결 시 완성 Scene 또는 sample JSON으로 진행한다.
복구는 포기가 아니라 진도 이탈 방지 장치입니다. 원인 기록은 남기고 학습 흐름은 유지합니다.

최종 시연

1문제 30초: 실제 PLC가 없어도 디지털 트윈 신호 흐름을 재현해야 했다.
2구조 60초: Scene A, Mock PLC, MQTT Broker, Scene B의 역할을 설명한다.
3시연 60초: Start → 물체 낙하 → X0 → Y20 → MQTT → Scene B 대시보드 변화를 보여준다.
4회고 30초: 가장 어려웠던 오류와 해결한 방법을 말한다.

평가

잘 만든 결과물의 기준

기능 기준

  • Start 버튼으로 물체가 생성된다.
