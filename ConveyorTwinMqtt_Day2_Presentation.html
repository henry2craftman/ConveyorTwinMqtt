DAY 02 / 메시지 읽기

상태와 계측값을 먼저 읽습니다

{
  "state": {
    "startButton": false,
    "objectDetected": true,
    "conveyorMotorOn": true
  },
  "measurements": {
    "temperatureC": 41.8,
    "vibrationMmS": 1.2,
    "currentA": 3.1,
    "rpm": 1420
  }
}

확인할 내용

  • state는 버튼·감지·모터의 논리 상태입니다.
  • measurements는 단위를 가진 계측값입니다.
  • 이 예시는 필드 학습용 발췌입니다.
  • 실제 발행 메시지에는 출처·시간·품질도 포함합니다.

확인 질문 · 완료 기준objectDetected=true와 conveyorMotorOn=true가 무엇을 뜻하는지 각각 설명한다.

DAY 02 / 메시지 읽기

출처·시간·품질과 raw를 검사합니다

schema: factory.conveyor.state.v1
source: unity-a-mock
mode: mock
timestamp: ISO 8601 시각
quality: good
connected: true
raw
  Y20: true
  X0: true
  D100: 418
  D110: 12
  D120: 31
  D130: 1420

확인 질문 · 완료 기준raw의 비트 값은 state와 일치하고, D 값은 measurements의 배율과 맞아야 한다.

강사 노트

위 블록은 읽기용 요약이며 JSON 입력용이 아닙니다. raw.D 값을 바꾸는 것만으로 현재 Subscriber의 계측값이 자동 변환되지는 않습니다.

DAY 02 / 실습 03

B 단독 수신으로 발행 경로를 분리합니다

  1. Scene A의 발행을 멈추고 Scene B만 실행합니다.
  2. Subscriber를 Explorer와 같은 Broker·state 토픽에 연결합니다.
  3. Explorer에서 상태 JSON을 발행합니다.
  4. Console의 Message queued와 Applied 로그를 확인합니다.
  5. 수신 데이터에 맞춰 대시보드가 바뀌는지 확인합니다.

확인 질문 · 완료 기준A가 꺼져 있어도 Explorer가 발행자가 되면 B는 갱신된다.

강사 노트

수동 실습 중 A가 계속 발행하면 테스트 값이 즉시 덮일 수 있습니다. 입력원이 하나인지 확인합니다.
